# Sanganak Works lander — code review

## Verdict

**Needs follow-up before calling the implementation fully acceptance-complete.** The production build, lint, unit tests, static route generation, required destinations, homepage asset, and homepage CTA exclusion all pass. The primary product gap is the missing navigation active state; the main additional risks are accessibility semantics, contradictory homepage documentation, and thin regression coverage for copy-heavy routes.

## Prioritized findings

### High

None found.

### Medium

#### 1. The shared navigation has no active-route state

- **Location:** `src/components/nav.tsx:6-11`, `src/components/nav.tsx:42-51`; `src/app/globals.css:118-135`
- **Impact:** Services never appears active on `/services`, and Careers never remains active on `/careers` or its nested role routes. Assistive technology also receives no `aria-current="page"`, so this fails the explicit Services/Careers navigation contract.
- **Evidence:** `Nav` does not read the current pathname and renders identical links on every route. The only underline/color behavior is for `:hover` and `:focus-visible`; no active selector or `aria-current` exists anywhere in app source.
- **Fix direction:** Derive the current route with `usePathname()`. Match Services exactly and Careers by `/careers` prefix, then set both a visual active class/data attribute and `aria-current="page"`. Add index and nested-route tests.

#### 2. Repeated primary navigation has no skip-to-content mechanism

- **Location:** `src/components/nav.tsx:17-55`; all page shells (for example `src/app/page.tsx:7-10` and `src/components/careers/role-detail.tsx:74-126`)
- **Impact:** Keyboard and switch users must traverse the same header links on every page before reaching the main content, leaving the pages without a WCAG 2.4.1 bypass block.
- **Evidence:** There is no skip link, and main elements have no shared focus target/id. Visible focus styling itself is present and good.
- **Fix direction:** Add a first-focusable “Skip to content” link in the shared shell and a stable target such as `id="main-content"` on the route main element (or move the shared shell into a layout that owns both).

#### 3. The manifesto complaint list is visually formatted text rather than a semantic list

- **Location:** `src/app/manifesto/page.tsx:10-16`, `src/app/manifesto/page.tsx:52-54`
- **Impact:** Screen readers announce one long paragraph instead of a three-item list, losing item count and list navigation despite the content being structurally a list.
- **Evidence:** The copy is stored as a newline-delimited template literal and rendered inside one `<p>` with `white-space: pre-wrap` (`src/components/editorial/editorial.module.css:217-219`).
- **Fix direction:** Keep the exact approved wording, including intentional source spelling, but render the introduction as a paragraph and the three complaints as `<ul><li>…</li></ul>`.

#### 4. The homepage source-of-truth document contradicts the enforced CTA requirement

- **Location:** `docs/research/home-paper.md:16`, `docs/research/home-paper.md:68`, `docs/research/home-paper.md:92`; current behavior at `src/components/home-hero.tsx:24-26` and `src/app/page.test.tsx:29-34`
- **Impact:** A future implementer following the research contract will restore the explicitly forbidden F9B-0 “ENTER THE MANIFESTO →” CTA and regress the current accepted behavior.
- **Evidence:** The live homepage and test correctly omit the CTA, while the research file says “Preserve it as a CTA,” “keep,” and “keep `ENTER THE MANIFESTO →` intact.”
- **Fix direction:** Amend the research contract with a superseding product decision that clearly says F9B-0 is intentionally omitted. Keep the existing negative regression test.

#### 5. Copy- and route-regression tests cover only a minority of acceptance-critical pages

- **Location:** `src/app/page.test.tsx`; `src/components/nav.test.tsx`; `src/app/careers/careers.test.tsx:25-43`
- **Impact:** Exact pricing, guarantee, manifesto wording, contact links, and three compact role pages can regress while all seven tests remain green.
- **Evidence:** There are no component tests for `/services` or `/manifesto`; Careers tests render only the index, Agent Engineer, and AI Engineer. Integration Engineer, Platform Engineer, and Design Lead are generated by the build but never asserted for content/links.
- **Fix direction:** Add table-driven assertions for every public route’s h1, critical exact copy, mailto/internal/external destinations, and one-h1/list semantics. Add an active-nav test with a mocked pathname.

### Low

#### 6. The internal manifesto link opts out of Next.js client navigation

- **Location:** `src/components/careers/role-detail.tsx:30-35`
- **Impact:** Clicking “our manifesto” performs a document navigation rather than using the App Router’s prefetch/client transition path, adding avoidable latency and resetting client state.
- **Evidence:** The helper renders a raw `<a href="/manifesto">`, while other internal links use `next/link`.
- **Fix direction:** Render this internal destination with `Link`; retain the existing class and accessible link text.

#### 7. No explicit browser security headers are configured

- **Location:** `next.config.ts:3-5`
- **Impact:** The static marketing site does not receive defense-in-depth headers such as Content-Security-Policy, Referrer-Policy, X-Content-Type-Options, or Permissions-Policy. Current exploitability is low because there are no forms, dynamic user content, auth, or app APIs.
- **Evidence:** A production response exposes only framework/cache/content headers; `poweredByHeader: false` is the sole security-related setting.
- **Fix direction:** Define a conservative header policy in Next config or at the deployment edge. Validate the CSP against Next font/image behavior before enforcing it.

#### 8. Next and its ESLint preset are on different patch versions

- **Location:** `package.json:13`, `package.json:27`
- **Impact:** `next` is `16.3.4` while `eslint-config-next` is `16.2.9`, which can create rule/runtime drift during upgrades even though lint currently passes.
- **Fix direction:** Pin the preset to the same Next release and update the lockfile together.

## Exact requirement checks

- **Homepage F9B-0 CTA:** Correctly absent. Source inspection found no CTA in `HomeHero`; the negative DOM test passes; production homepage HTML does not expose an “ENTER THE MANIFESTO” link.
- **Homepage FMQ-0 asset:** Correctly uses `/brand/computer-logo-fmq-0.svg` at `src/components/home-hero.tsx:31-38`. Its SHA-256 is `b5ee2e139de72a2af81bb9d7aa04c99d0dcde913469720fdb51f508ad08759f1`, exactly matching the extraction manifest.
- **Primary nav destinations/order:** Saras → `https://saras.works`, Masala Dew → `https://masaladew.com`, Services → `/services`, Careers → `/careers`; source and DOM tests agree. Both external sites returned HTTP 200 after redirecting to their `www` canonical hosts.
- **Contact/apply destinations:** Services and Manifesto use `mailto:contact@sanganak.works`; every role uses the shared `APPLY VIA EMAIL →` mailto CTA.
- **Route coverage:** `/`, `/services`, `/manifesto`, `/careers`, and all five role-detail routes were emitted as static routes and returned HTTP 200. A deliberately missing route returned 404.
- **Responsive source audit:** Home stacks below 1024px and collapses nav below 768px; editorial and Careers two-column layouts stack at their defined breakpoints. Mobile gutters, fluid headings, card heights, and 42–60px primary controls avoid an obvious 320px source-level overflow. No material source-level performance issue was found: all routes prerender statically, the only shared client component is the small navigation, and the required SVG is 20 KB on disk.

## Positive observations

- All pages use one visible h1 and semantic main/section/article structures; role-detail bullet content uses real lists.
- Focus-visible outlines exist globally and on card/contact/apply links; touch controls meet a practical 42px minimum.
- The mobile menu has an accessible name, `aria-controls`, and synchronized `aria-expanded` state.
- External Saras links that deliberately open a new tab include `rel="noopener noreferrer"`.
- Reduced-motion styles disable decorative transitions.
- No secrets, dynamic HTML injection, unsafe URL construction, forms, API routes, or server-side mutations were found.

## Residual risk

No browser-driven screenshot diff or automated accessibility scan was completed, so pixel-level parity, actual layout at browser zoom, contrast calculations, focus behavior across real browsers, and Core Web Vitals remain unverified. The project also has no end-to-end navigation tests; the HTTP smoke test verifies availability but not interactive client transitions or mobile menu behavior in a real browser.
